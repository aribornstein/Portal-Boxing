# PORTALAR Implementation Plan

Status: active. This plan is an engineering contract, not a completion claim. A phase exits only when its automated criteria pass and hardware-only checks are either recorded as passed on a Quest 3 or remain explicitly pending.

## Shared Rules

- Runtime systems use IWSDK ECS and import Three.js APIs only from `@iwsdk/core`.
- Unsupported WebXR surfaces live behind typed adapters; no adapter may fabricate capability data.
- Gameplay logic is deterministic and independent from rendering, XR frames, and model inference.
- Sparse depth samples are probes. Only a separately validated reconstruction may become a mesh collider.
- Safety-sensitive and low-confidence objects are restricted until user confirmation.
- Every resource owner exposes cleanup and restart is tested for duplicate loops, listeners, entities, workers, and GPU resources.

## Validation Loop

For each coherent increment: inspect declarations and owner code, make one focused edit, run the narrowest test, then run typecheck/build as applicable. Record browser, IWER, inference, performance, cleanup, and hardware evidence in `docs/validation-log.md`. An unexplained failure blocks the next dependent increment.
